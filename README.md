🧭 Roadmap
🔴 Phase 1 — Basics · Completed
Cleave: cutting through the fundamentals. I have covered these concepts at a
foundational level and am now building on them through practice.

HTML: semantic structure, forms, and accessibility basics

CSS: box model, selectors, specificity, and the cascade

Flexbox and Grid for layouts

Responsive design: media queries and mobile-first thinking

JavaScript fundamentals: variables, functions, arrays, objects, ES6+

DOM manipulation and event handling

Async JavaScript: promises, async/await, and the Fetch API

Git, GitHub, npm, and browser DevTools basics
🟠 Phase 2 — Intermediate · In progress
Dismantle: breaking interfaces into clean, reusable pieces. My current focus
is understanding how frontend features fit together and writing them more
reliably.

React: components, props, state, and the rendering model

Hooks: useState, useEffect, useRef, useContext, and custom hooks

Routing: client-side navigation with React Router

Forms: controlled inputs, validation, and user feedback

API integration: Fetch/Axios, loading states, and error states

Authentication on the client: login flows, protected routes, token handling

State management: Context API, then Redux Toolkit or Zustand

Styling at scale: Tailwind CSS, CSS modules, and design consistency

Project structure: components, pages, hooks, services, and utilities

Browser storage: localStorage, sessionStorage, and cookie basics

Real-time basics: Socket.IO client fundamentals

Deployment: Vercel/Netlify, environment variables, and build errors
⚫ Phase 3 — Advanced · Pending
Malevolent Shrine: mastering the whole domain. Next, I want to move beyond
building screens and learn how to design fast, accessible, scalable frontends.

TypeScript: typing props, state, API responses, and events

Next.js: SSR, SSG, routing, and data fetching

Performance: Core Web Vitals, code splitting, lazy loading, memoization

Canvas API: drawing, pointer events, and rendering loops

Scalable real-time UIs: reconnection, optimistic updates, and state sync

Advanced state design: server state vs client state, caching with TanStack Query

Accessibility (a11y): keyboard navigation, ARIA, and contrast

Testing: unit tests, component tests, and end-to-end tests

Animation: CSS transitions, Framer Motion, and motion that serves the UI

Frontend security: XSS, CSRF awareness, and safe handling of user content

Tooling: Vite internals, linting, formatting, and CI/CD checks

Architecture: design systems, reusable component libraries, and trade-offs

🚀 Applying what I learn — SketchVerse (Frontend)
The frontend of my upcoming project, SketchVerse, a multiplayer
drawing-and-guessing game inspired by the web-app game skribbl.io. This is
where everything on the roadmap comes together. Some of its features:
Login and registration screens with protected routes
Lobby UI: create a room, join a room, and see the player list
A real-time drawing canvas with brush, colors, eraser, and undo
Live chat and guess input with instant feedback
Round timers, scoreboards, and game-state transitions
Responsive layout that works on desktop and mobile
Clear loading, error, and reconnection states
The long-term goal is to understand not only how to make an interface look good,
but also how to make it fast, accessible, and maintainable.

🔁 How I learn
Understand the concept and why it is needed.
Build a small working implementation.
Test normal and edge cases (and different screen sizes).
Debug errors and understand their causes.
Refactor toward cleaner, more reusable components.
Apply the concept to a real project.
▶️ Run a practice project (Basic)
git clone <https://github.com/BilalAhmad7777/FRONTEND-LEARNING.git>
cd FRONTEND-LEARNING

# Enter the specific project folder
cd FRONTEND/1st-part

npm install
npm run dev
​
Note: The projects in this repository were made only for basic learning
purposes and do not showcase the full extent of my skills. I like to improve
myself every day and I am going to study frontend development even further in
the upcoming months to gain deep knowledge of it.
Check each project's package.json for its actual start command. Some
projects may use npm start or open directly in the browser.
🔐 Security reminder
Never commit .env files, API keys, or real user tokens, and remember that
anything shipped to the browser is visible to the user. Keep secrets on the
backend and use a safe .env.example to document required variables.
